# 阶段执行规范

这些细项供复杂批次参考，不要求每次逐项生成报告。按任务指定范围执行，质量判断均采用静态阅读，不实际运行资源。

## 1. 搜集

**输入：**目标能力、包含与排除范围、已有资源清单。

**操作：**

1. 把主题转成有限的检索方向，优先找原始仓库、作者文档或官方资料。
2. 对照现有清单及 [变更记录](../../resources/CHANGELOG.md)，核对重命名、镜像、同名不同作者、重复链接和历史排除原因；不要仅按项目名合并。
3. 先查看简介与目录，记录对象和目标范围的关联；宣传性描述标为作者自述。
4. 按任务需要获取本地资料。访问失败或未获取时记录状态和原因，不用相似项目代替。
5. 在任务单记录检索渠道、关键词、覆盖边界及未能获取的对象。

**输出：**候选记录，包括 ID、名称、公开来源、资源类型、发现理由和获取状态。可使用资源卡模板先填写来源部分。

**退出条件：**每个候选身份可核对；已有资源与新增候选已区分；搜集范围和缺口明确。此时不下质量结论。

## 2. 整理

**输入：**候选记录，以及可访问的目录和文件。

**操作：**

1. 先读 README 和目录，再定位核心规则、参考资料、模板及脚本，不一次读完整大型合集。
2. 区分仓库容器、具体能力内容和依赖材料。以能够单独描述价值的内容作为分析对象。
3. 给每个对象标注能力类别和学科范围；允许多标签，不强迫所有资源互斥归类。
4. 标出相关资源的包含、相似、共享文件或派生关系。仅有相同措辞或文件名时，写待核对，不推断来源先后。
5. 在资源卡登记关键路径和待阅读内容，避免后续重复定位。

**输出：**资源卡的结构、模块、关系及阅读范围。

**退出条件：**能明确指出接下来要读哪些文件，以及这些文件各自代表什么。文件数量只作描述，不用于价值排序。

## 3. 汇总

**输入：**已整理资源、实际阅读的核心文件。

**操作：**

1. 按资源卡模板概括问题范围、内容构成、关键机制、具体资产和限制。
2. 每条重要描述标注依据类型：`源码核对`、`作者自述`、`分析推断`、`未知`。
3. 依据必须包含可定位的文件与章节；引用公共网页时保留准确链接和访问日期。
4. 区分“要求 Agent 做某事”和“提供实现该功能的脚本”。脚本存在也不等于运行正确。
5. 明确未读内容。缺少的能力写成“本次阅读范围内未发现”，除非完整检查足以支持更强结论。

**输出：**完整资源卡。优先简短、可比较的归纳，避免大段复述 README。

**退出条件：**另一名协作者能依据资源卡定位关键内容，并区分已确认事实和待验证判断。

## 4. 初筛

**输入：**资源卡、目标范围、已有同类记录。

**操作：**

1. 检查与目标能力的关联，区分直接相关、部分相关和范围外。
2. 检查是否有实质内容，以及重要规则是否存在明显冲突或僵化假设。
3. 对重复候选先做局部对照；不能只因仓库定位相似就判定无增量。
4. 分流为 `继续深审`、`暂缓` 或 `建议排除`，逐条写明理由。
5. 信息不足归入暂缓；Star、内容数量、项目新旧或尚未运行，不单独构成淘汰理由。

**输出：**资源卡中的初筛建议与依据。建议排除的对象仍需复核，不能直接成为最终淘汰结论。

**退出条件：**每项分流都有目标关联和内容依据；不确定项已显式保留。

## 5. 价值判定

**输入：**深审候选、核心文件和针对同一能力的比较对象。

**操作：**

1. 围绕具体能力建立对比表，对齐分析范围；不把大型科研框架与单个润色模块直接排总榜。
2. 针对关键主张补读规则、参考资料或脚本，核对实际机制及其前提。
3. 分别判断：目标相关性、独特增量、内容具体性、依据可靠性、可提取价值、理解与维护成本。
4. 每项写 `高`、`中`、`低` 或 `无法判断`，并附依据。不要用平均总分掩盖关键缺陷。
5. 明确价值属于规则、参考材料、模板、脚本还是框架设计；同一仓库允许不同内容有不同结论。
6. 使用决策模板提出 `重点保留`、`部分保留`、`参考保留`、`暂缓` 或 `淘汰`，说明适用边界和重新审查条件。

**输出：**对比表和决策草案。没有同类材料时可提出有条件的价值判断，但不能宣称优于其他资源。

**退出条件：**能回答“值得保留的具体内容是什么、增量在哪里、依据是什么、还不能确定什么”。

## 6. 复核与归档

**输入：**资源卡、对比表及决策草案。

**操作：**

1. 回到原始文件核对所有支撑保留或淘汰结论的关键依据；辅助描述按风险抽查。
2. 检查摘要是否把作者宣传升级为事实，或把静态分析升级为功能效果验证。
3. 检查比较对象是否对齐，是否遗漏明显差异，替代资源是否实际覆盖被淘汰的内容。
4. 检查“未发现”“不能判断”“没有价值”是否被错误混用。
5. 证据缺失退回汇总；比较不充分退回价值判定；对象身份或模块划分有误退回搜集或整理。
6. 通过后将结论标为已复核，更新任务单。若需要同步总索引，在对应索引中链接决策记录，不凭空增加分数或排名。

通过检查并实际入库后，登记作用与适用范围。发生入库、修改、删除、排除或恢复时，更新 [变更记录](../../resources/CHANGELOG.md)，连同相关文件形成 Git commit。删除时保留原因；恢复时保留旧记录并追加新依据。

**输出：**已复核结论或带明确原因的退回记录；任务单包含恢复位置。

**退出条件：**完成标准满足，或未完成项及原因被准确交付。未实际核验的草案不能标为已复核。
