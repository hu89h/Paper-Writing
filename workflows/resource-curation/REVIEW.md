# 资源维护流程审查

日期：2026-10-15。依据三个候选的实际静态审查与本地 Git 记录，检查流程的判断边界和维护成本。此文记录流程问题及修订依据；具体资源结论以入库目录和资源变更表为准。

## 实际处理覆盖

| 对象 | 处理结果 | 对流程的检验 |
| --- | --- | --- |
| [Master-cai 写作参考](../../resources/reviews/research-paper-writing-skills.md) | 部分入库：反向提纲、局部检查及 Method 组织参考 | 与 CCFA 目的高度重合，仍可保留更具体的步骤；整份 Skill 默认要求不随局部内容通过 |
| [jin-s13 证据工具](../../resources/reviews/ai-research-writing-skill.md) | 部分入库：研究交接、来源数值重算和构建记录设计 | 文档、schema 与实现必须分开核对；数值集合匹配不能证明正确语义归属；直接依赖影响结论 |
| [citation-check](../../resources/reviews/citation-check-skill.md) | 正式排除，保留原件与历史决定 | 可以因自身核心质量问题排除，不必先证明完全重复；已撤销的旧决定不能当最新状态 |

三项处理逐项登记并分别形成本地提交，后项只将此前已登记范围用作已入库比较基准。当前 23 个接收仓库中，3 个部分入库、1 个正式排除、19 个尚未形成正式结论；仓库内部未审模块不因此获得通过。

## 发现与已落实的优化

| 原流程不足 | 本次证据及后果 | 修订 |
| --- | --- | --- |
| 强调重合与独特增量，但没有清楚说明“同样目的、更具体材料”的价值 | Master-cai 与 CCFA 都讲段落和 Method；若只按功能重合，反向提纲的明确步骤会被误删；若按新能力入库又会重复计数 | 比较具体步骤、示例、接口和实现的补充价值，同时考虑维护成本；调整对比及决策模板，不要求证明全仓唯一 |
| “部分保留”没有要求精确到内容层级 | Master-cai 的段落检查值得留，而默认输出合同和普适实证接收规则不宜整体采用；jin-s13 的来源重算与稿件集合匹配质量也不同 | 定位到文件、小节或函数，注明规范／示例／接口／实现设计；已否定的前提不能靠“供参考”整体通过 |
| 静态质量说明偏原则，容易只检查文档与文件存在 | jin-s13 的输入来源确实会重算，但稿件匹配丢失了方法、指标和位置归属 | 对关键能力追读直接依赖，核对输入到输出的逻辑，必要时构造静态反例；不把反例推理写成测试结果，也不扩展为全仓代码审计 |
| 同批候选的比较顺序不够明确，来源关系也未提示 | jin-s13 README 明示受 Master-cai 启发；先前 citation-check 的排除曾误用待审材料作已有覆盖 | 每项写清决定时的基准；只有已登记项进入后续已入库比较，共同来源不当独立验证 |
| 多份辅助模板容易诱发重复记录，缺少简洁完成标准 | 本次每项只用一份分析，已经覆盖范围、质量、比较、决定；重复创建四份表没有必要 | 主流程明确一份 Markdown 可兼任多种记录；按结论需要阅读，材料足以支持限定决定即停止，未读部分单独标明 |
| “未入库”仍可能被默认理解为“待审”，历史撤销也容易被忽略 | citation-check 现在正式排除，但 README 原文把全部未入库材料描述成候选 | README 改为最新有效决定确定状态；提交前人工核对目录、模块、审查说明及变更表一致。接收校验脚本不承担质量或状态语义判断 |
| 删改说明没有要求检查同库剩余项及跨资源依赖 | CCFA 有共享模块，jin-s13 的检查器依赖共享解析及数值登记逻辑；撤下一个入口可能留下依赖该内容的入库条目 | 缩小范围时同步当前记录；删除时检查剩余依赖与引用，区分历史证据和当前能力，保留旧原因。此项是根据结构作出的维护推断，尚非实际删除测试 |

修订已进入 [主流程](WORKFLOW.md)、[参考细项](STAGES.md) 和相关可选模板；模块表也区分未审内容与明确不采用的规则。仍由 Agent 直接维护 Markdown 和现有接收清单，用本地 Git 记录变更。

维护检查通过：`scripts/verify_resources.py` 核对 23 个上游仓库、32 个接收入口与 Git 状态；共享文件的 192 个本地链接、8 个章节链接及表格列数有效；`git diff --check` 通过。原始上游工作树保持干净，检查过程未执行候选代码。

- 三个案例不能证明评分一致性、跨 Agent 一致性或长期维护成本已经可控；也没有资源的运行准确率或写作效果数据。
- 后续遇到真实删改、恢复或暂缓任务时，用该次实际改动检查是否遗漏依赖、旧状态或重新考虑条件；不为测试流程制造无实际理由的删改记录。
