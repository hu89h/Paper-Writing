# 仓库接收、审查与维护工作流

## 目标

输入是已经提供的仓库。指导 Agent 检查它自身的质量、与现有资源的重合及增量，决定是否保留，通过后登记作用，并维护后续删改及其原因。

可以执行完整流程，也可以只执行指定部分。只修改工作流时，不启动资源评审或变更现有资源。

质量检查只做静态分析，不运行候选 Skill、脚本或实验，也不安装其依赖。

## 开始前

1. 明确对象、目标范围和本次做到哪一步；能从任务推断的内容自行判断。
2. 查看 [已入库资源](../../resources/CATALOG.md)、[已入库模块](../../resources/MODULES.md) 和 [变更记录](../../resources/CHANGELOG.md)；接收位置及待审线索见 [已接收仓库](../../resources/RECEIVED.md)。下载或登记来源不等于入库。
3. 曾删除或排除的资源先核对原原因，避免重复添加。

## 1. 接收已有仓库

确认提供的仓库名称、来源和可阅读位置，查看是否已经登记，或曾被删除、排除。注意改名、镜像、同名不同作者和明显派生关系。

直接使用提供的材料开始审查。材料无法阅读时说明缺口；发现和搜集候选仓库不属于本流程。

## 2. 检查自身质量

先读简介与目录，再有选择地阅读核心规则、参考资料和脚本：

检查内容是否实质、规则是否合理且自洽、假设与适用范围是否清楚、宣称的能力是否有对应内容。

区分作者自述、源码事实、分析推断和未知。脚本存在不等于功能已验证。可以只保留一个仓库中的部分内容，不必给整仓库一个统一结论。

## 3. 比较现有重合与增量

以当前已入库目录及其保留范围为比较基准，按具体能力比较覆盖、增量和替代关系。需要比较时回到双方原文，不凭简介相似就判定完全重复。

当前没有已入库资源时，将此项记为“不适用：已入库资源为空”，继续检查自身质量及目标相关性。第一项资源不因缺少对照就自动通过，也不能据此宣称独特或优于其他资源。

其他待审候选可作为额外线索，但不能充当已有覆盖或现成替代的依据。入库目录与变更记录的最新有效结论应一致；发现冲突先核实并补正，不能仅因目录中有来源链接就认定已入库。

## 4. 决定处理结果

| 结果 | 后续处理 |
| --- | --- |
| 保留 | 登记作用、适用范围和保留理由 |
| 部分保留 | 明确保留哪些内容，以及其余内容不保留的原因 |
| 暂缓 | 说明尚不能判断的关键问题 |
| 不保留 | 记录质量问题、重复或范围不适合等具体原因，必要时注明替代资源 |

判断应有关键原文依据，不必制造总分或排名。较复杂的分析可参考 [阶段规范](STAGES.md) 和配套模板。

## 5. 登记与记录

通过检查后，更新相关资源目录和模块入口，说明它的作用、适用范围，以及值得保留的具体内容。按需同步仓库清单和 Git submodule。

`CATALOG.md` 与 `MODULES.md` 由维护者直接更新，只登记通过静态审查的范围；部分保留时明确其余内容是暂缓、未审查还是不保留，以及原因。不要求删除原始仓库。

`repositories.json` 与 `modules.json` 只记录已接收材料及入口线索，脚本由此生成 `RECEIVED.md` 与 `RECEIVED_MODULES.md`，不改写入库记录。只有接收内容或线索发生变化才同步这些文件；入库不要求新增 JSON 状态字段。

详细审查说明按需保存为 Markdown，并从目录和变更表链接；简单结论直接写变更表即可，不要求单独创建报告。

在 [变更记录](../../resources/CHANGELOG.md) 追加入库及其理由。不保留的资源追加排除记录，避免之后重复引入；暂缓的记录待判断事项。

## 后续修改、删除与恢复

- **修改：**说明改了什么；检查受影响的描述、模块入口和比较结论，同步相关文件。内容变化会影响原检查结论时，补做对应检查。
- **删除：**从当前目录中移除不再保留的条目，处理相关引用，并在变更记录中写清来源和删除原因。需要清理本地仓库时按任务范围处理，不把决策记录一并删掉。
- **恢复：**先看历史删除或排除原因，说明情况发生了什么变化，重新检查后再恢复；追加新记录，保留原原因。

维护由 Agent 直接使用现有文件和 Git 工具完成。

## 6. 检查与提交

检查本次实际改动：相关条目与链接是否一致、原因是否写清、是否误改无关内容。需要时使用已有检查脚本。

一次完整的资源变更形成一个本地 Git commit，包含相应目录、来源配置和变更记录。不要捎带无关改动，不自动推送。

简单维护直接更新相关文件和变更表即可。复杂批次可使用 [任务单](templates/task.md)、[资源卡](templates/resource-card.md)、[对比表](templates/comparison.md) 和 [决策记录](templates/decision.md)；这些是辅助模板，不是每次必须填满的表单。

中断或交接时说明已完成内容、实际产物和下一步；恢复时复用已有工作，不重复整个流程。
